# 2026-10-30 — fleet SQLite backups: Central-time schedule, 2-day local, B2 3+2 with 14-day cap

## Why

Jay (2026-10-30): the "at most 2 weeks" window counts from day 1.  With
3 daily + 2 weekly (Sunday) sets and no age cap, the older Sunday set lived
until the next Sunday rolled it out, so it could reach about 15-16 days.

## What changed

`scripts/ops/fleet-sqlite-backup.sh` `prune_b2_sets`:

- New `B2_MAX_AGE_DAYS` (default 14).  After the daily/weekly (or legacy
  `B2_KEEP_SETS`) picks, any dump set whose stamp is more than N days older
  than the current run's stamp is deleted, whatever the keep counts say.
  Non-numeric or `< 1` values fall back to 14; the cap cannot be disabled.
  The current set is never deleted.
- Weekly picks are one set per distinct Sunday (UTC) date, and a Sunday already
  covered by a daily does not take a weekly slot.  (Before, a 6-hourly lane in
  daily/weekly mode could spend both weekly slots on one Sunday.)
- The function now sits above the `FLEET_BACKUP_LIB_ONLY` return so
  `scripts/ops/test-fleet-sqlite-backup.sh` can test it offline with an
  `rclone` stub.

`scripts/ops/fleet-backups.cron`: rewritten — see the schedule section.

## Schedule + local retention (Jay 2026-10-30, 1:08am/1:09am CT)

Times are deliberately offset and not evenly spaced — do not round them.

| App | Local dumps (Central) | Local keep | B2 |
|---|---|---|---|
| Socratic.Trade | 6:30am + 7:30pm | 4 (`KEEP_COUNT=4`, `KEEP_DAYS=2`) | 3 daily + 2 weekly, 14d cap |
| Congress.Trade | 6:00am + 8:00pm | 4 (`KEEP_COUNT=4`, `KEEP_DAYS=2`) | 3 daily + 2 weekly, 14d cap |
| Usage-Monitor | 8:30pm | 2 (`KEEP_COUNT=2`, `KEEP_DAYS=2`) | 3 daily + 2 weekly, 14d cap |

UM's previous local keep (11 / 40 days in the repo cron) is replaced.  Each
app gets its own cron lane and lock.

Host cron is UTC and Ubuntu's cron has no `CRON_TZ`, so each line fires at both
the CDT (UTC-5) and CST (UTC-6) UTC times for its slot; the new
`FLEET_BACKUP_CT_HOURS` gate in the script (checked before the lock, log, or
any dump) lets only the run whose `America/Chicago` hour matches through.  The
gate fails open if the zoneinfo file is missing.  The host health check's
36-hour staleness limit stays above the longest gap (UM, 24h).

B2 dailies are now the newest set of each of the newest 3 UTC dates, so the
twice-daily lanes keep ~3 days rather than 1.5.

## Resulting B2 shape (UM, daily)

- Always the last 3 days.
- Weekly copies at about 1-7 days and 8-14 days old (exactly 7 and 14 on
  Sundays).  Nothing on B2 `hetzner/` dump sets is older than 14 days.

## Not changed

- Litestream prefixes, `qdrant/`, and the R2 weekly leg.

## Deploy

The host runs `/usr/local/sbin/fleet-sqlite-backup.sh` and
`/etc/cron.d/fleet-backups`; this change does nothing until those are
reinstalled from the repo.
